Ordenado por dependencias tecnicas




Introduccion

Este documento define el orden exacto de implementacion para los nuevos modulos del sistema. Las fases estan ordenadas por dependencias: no se debe avanzar a la siguiente fase sin tener las tablas SQL creadas y el servicio probado en Swagger.



Cada tarea sigue el flujo estandar del proyecto:


DTO  -&gt;  Features/{Modulo}/Dtos/


Interfaz  -&gt;  Features/{Modulo}/Interfaces/


Servicio  -&gt;  Features/{Modulo}/Services/  (retorna Result&lt;T&gt;)


Controller  -&gt;  usa HandleResult(resultado)


SQL  -&gt;  script manual en SQL Server + DbSet + QueryFilter(e =&gt; e.Activo)



Las etiquetas al final de cada tarea indican que artefactos hay que crear:

[SQL] = tabla o ALTER TABLE en SQL Server   [DTO] = clases de request/response   [SVC] = logica en Services/   [CTRL] = endpoint en Controller


FASE 1
Catalogos base
Proveedores · Clientes · Productos — sin estas entidades, nada mas puede arrancar



Estas tres entidades ya existen en la base de datos. El trabajo consiste en exponer CRUD completo via API, agregar los campos de trazabilidad a Productos y aplicar las validaciones de negocio.



1
Proveedores — CRUD completo



La entidad Proveedores ya existe. Crear ProveedoresService e implementar: listar activos, obtener por Id, crear, editar, borrado logico (Activo = false). Validar que no se borre un proveedor que tenga compras activas. Si el negocio maneja RNC/NIT, agregar campo y validar unicidad con == (no StringComparison).
[DTO]  [SVC]  [CTRL]

Clientes — CRUD completo



La entidad Clientes ya existe. ClientesService con los mismos endpoints que Proveedores. Agregar campo TipoCliente (Natural/Juridico) si no existe — requiere ALTER TABLE. Validar que no se elimine un cliente que tenga ventas con estado distinto a Cancelado.
[SQL]  [DTO]  [SVC]  [CTRL]



3
Productos — CRUD + campos de lote y serie



Agregar tres columnas a la tabla Productos: TieneNumeroSerie (BIT NOT NULL DEFAULT 0), TieneLote (BIT NOT NULL DEFAULT 0), CodigoBarras (NVARCHAR(100) NULL). Ejecutar ALTER TABLE antes de modificar la entidad POCO. ProductosService debe validar que el CodigoBarras no este duplicado usando ==.

FASE 5
Administracion del SAR
Facturacion fiscal Honduras — CAI, correlativos, ISV 15% y 18%



El SAR depende de que Productos tenga TipoISV, que Clientes pueda almacenar RTN y que el flujo de pagos (Fase 3) este completo. El numero de factura debe generarse atomicamente para evitar correlativos duplicados en concurrencia.



13
Tabla ConfiguracionSAR



Un registro activo por sucursal. Almacena el CAI vigente, el rango de correlativos autorizado y la fecha limite de emision. Solo un usuario con rol Admin puede crear o renovar la configuracion. Al vencer FechaLimiteEmision o al alcanzar RangoHasta, el servicio debe retornar Result.Fail indicando que se debe renovar el CAI.
[SQL]  [SVC]



14
Tabla FacturasEmitidas



Una factura por venta (relacion 1:1, VentaId tiene indice unico). Almacena el desglose fiscal: MontoExento, MontoGravado15, MontoGravado18, ISV15 calculado, ISV18 calculado. RTNCliente es nullable (consumidor final no requiere RTN). El campo NumeroFactura almacena el numero con formato SAR.
[SQL]  [DTO]  [SVC]



15
SARService — generar numero de factura



Al confirmar una venta: (1) verificar ConfiguracionSAR activa para la sucursal, (2) verificar que CorrelativoActual &lt; RangoHasta y que DateTime.UtcNow &lt; FechaLimiteEmision, (3) formatear numero con formato SAR: 000-001-01-00000001, (4) incrementar CorrelativoActual e insertar FacturaEmitida en el mismo SaveChanges para garantizar atomicidad.
[SVC]



16
Calculo de ISV 15% y 18%



Agregar columna TipoISV a Productos (NVARCHAR(10): Exento / ISV15 / ISV18). Al emitir factura, SARService recorre los VentasDetalles y acumula: MontoExento (productos Exento), MontoGravado15 (productos ISV15), MontoGravado18 (productos ISV18). ISV15 = MontoGravado15 * 0.15, ISV18 = MontoGravado18 * 0.18. Reflejar el desglose en el DTO de respuesta.
[SQL]  [SVC]



17

POST /api/sar/configuracion (crear o renovar CAI — solo Admin)  |  GET /api/sar/configuracion/actual  |  POST /api/ventas/{id}/emitir-factura (puede llamarse automaticamente al cambiar estado a Pagado)  |  GET /api/ventas/{id}/factura (retorna el PDF o el DTO de la factura emitida).

2. Interfaz (Features/{Modulo}/Interfaces/)
public interface IProveedoresService
{
    Task&lt;Result&lt;List&lt;ProveedorResponseDto&gt;&gt;&gt; ListarAsync();
    Task&lt;Result&lt;ProveedorResponseDto&gt;&gt;      ObtenerPorIdAsync(int id);
    Task&lt;Result&lt;ProveedorResponseDto&gt;&gt;      CrearAsync(ProveedorCreacionDto dto);
    Task&lt;Result&lt;ProveedorResponseDto&gt;&gt;      EditarAsync(int id, ProveedorCreacionDto dto);
    Task&lt;Result&lt;bool&gt;&gt;                      EliminarAsync(int id);
}




3. Servicio (Features/{Modulo}/Services/)
public class ProveedoresService : IProveedoresService
{
    private readonly WebWaveDbContext _context;
    public ProveedoresService(WebWaveDbContext context) =&gt; _context = context;
 
    public async Task&lt;Result&lt;ProveedorResponseDto&gt;&gt; CrearAsync(ProveedorCreacionDto dto)
    {
        var existe = await _context.Proveedores
            .AnyAsync(p =&gt; p.RTN == dto.RTN);  // == no StringComparison
        if (existe)
            return Result&lt;ProveedorResponseDto&gt;.Fail(&quot;Ya existe un proveedor con ese RTN.&quot;);
 
        var proveedor = new Proveedor
        {
            Nombre   = dto.Nombre,
            Contacto = dto.Contacto,
            RTN      = dto.RTN,
            Activo   = true
        };
        _context.Proveedores.Add(proveedor);
        await _context.SaveChangesAsync();
 
        return Result&lt;ProveedorResponseDto&gt;.Ok(MapToDto(proveedor));
    }
 
    private static ProveedorResponseDto MapToDto(Proveedor p) =&gt; new()
    {
        Id      = p.Id,
        Nombre  = p.Nombre,
        Contacto = p.Contacto,
        RTN     = p.RTN
    };
}




4. Controller (Controllers/)
[ApiController]
[Route(&quot;api/[controller]&quot;)]
[Authorize]
public class ProveedoresController : BaseApiController
{
    private readonly IProveedoresService _svc;
    public ProveedoresController(IProveedoresService svc) =&gt; _svc = svc;
 
    [HttpGet]
    public async Task&lt;IActionResult&gt; Listar()
        =&gt; HandleResult(await _svc.ListarAsync());
 
    [HttpPost]
    public async Task&lt;IActionResult&gt; Crear([FromBody] ProveedorCreacionDto dto)
        =&gt; HandleResult(await _svc.CrearAsync(dto));
 
    [HttpPut(&quot;{id}&quot;)]
    public async Task&lt;IActionResult&gt; Editar(int id, [FromBody] ProveedorCreacionDto dto)
        =&gt; HandleResult(await _svc.EditarAsync(id, dto));
 
    [HttpDelete(&quot;{id}&quot;)]
    public async Task&lt;IActionResult&gt; Eliminar(int id)
        =&gt; HandleResult(await _svc.EliminarAsync(id));
}
